Cyber Lab Repo + Codex + Claude Code Setup Plan

Goal
Create a GitHub-backed cyber lab repository that both Codex and Claude Code can use to:
- Create lab directories
- Pull shared templates
- Write lab setup guides
- Store hardware requirements
- Store config files
- Store expected outputs
- Store actual results
- Open issues and pull requests
- Review each other's work through GitHub

Important reality check
Codex and Claude Code should not directly control each other.

The reliable workflow is:
- GitHub repo is the shared source of truth
- Codex writes files, branches, commits, and PRs
- Claude Code reads those files, reviews them, edits them, and comments through GitHub
- They coordinate through issues, PR comments, branch names, and repo instructions

Do not use either agent to directly configure live lab machines until you explicitly decide to allow that later.

# AGENTS.md

## Role

This repository is a personal cybersecurity lab knowledge base. Codex should help create, organize, and maintain reproducible lab files.

## Primary responsibilities

Codex may:
- Create lab directories
- Fill in lab template files
- Write setup instructions
- Write hardware lists
- Write topology documentation
- Write expected output files
- Write result summaries
- Create config files
- Create scripts
- Create GitHub issues
- Create branches
- Open pull requests
- Update documentation

## Hard rules

- Do not modify live lab machines.
- Do not SSH into real devices unless explicitly instructed.
- Do not assume hidden local state.
- All work must be reproducible from committed files.
- Prefer documentation, templates, scripts, and infrastructure-as-code.
- Do not store real passwords, API keys, tokens, private keys, or personal secrets.
- Use credentials.example.md for placeholder credentials only.
- Keep each lab self-contained.
- Keep instructions granular and beginner-friendly.
- Every lab must include setup, tasks, expected output, cleanup, and learning objectives.

## Required lab structure

Each lab should use this structure:

labs/000-lab-name/
  README.md
  objectives.md
  hardware.md
  topology.md
  setup.md
  instructions.md
  expected-output.md
  results.md
  cleanup.md
  lessons-learned.md

    logs/

Use this naming style:

002-service-enumeration
003-ssh-bruteforce
004-dvwa-sql-injection
005-wazuh-detection

## Agent coordination

Use the agent-handoff folder for coordination.

PART 21 - Configure Codex MCP for GitHub

Codex MCP configuration is normally stored in your Codex config file.

Create the config folder:
mkdir -p ~/.codex

Open the config:
nano ~/.codex/config.toml

Add a GitHub MCP server entry.

Use this general pattern:

[mcp_servers.github]
command = "docker"
args = ["run", "-i", "--rm", "-e", "GITHUB_PERSONAL_ACCESS_TOKEN", "-e", "GITHUB_TOOLSETS=repos,issues,pull_requests", "ghcr.io/github/github-mcp-server"]
env = { GITHUB_PERSONAL_ACCESS_TOKEN = "${GITHUB_PAT}" }

Save the file.

Notes:
- This uses the official GitHub MCP server container.
- It limits toolsets to repo, issue, and pull request work.
- If variable expansion does not work in your Codex version, replace "${GITHUB_PAT}" with your token locally, but never commit that config file.

PART 25 - Add GitHub MCP to Claude Code

Use the official GitHub remote MCP server through Claude Code.

From inside the repo:

claude mcp add --transport http github https://api.githubcopilot.com/mcp/ \
  --header "Authorization: Bearer $GITHUB_PAT"

If you want it project-scoped instead of user-scoped, use:

claude mcp add --transport http --scope project github https://api.githubcopilot.com/mcp/ \
  --header "Authorization: Bearer $GITHUB_PAT"

Important:
- User-scoped config is private to your machine.
- Project-scoped config may create or update .mcp.json in the repo.
- Do not commit real tokens into .mcp.json.
- Prefer environment variables for secrets.

PART 31 - Recommended agent workflow

For creating a new lab:

1. You create a GitHub issue:
Lab 002 - Service Enumeration

2. Ask Codex:
Create lab 002 from templates/lab-template. Use the issue requirements. Create a branch, commit the files, and open a PR. Do not modify live systems.

3. Ask Claude Code:
Review the PR for lab 002. Check reproducibility, command accuracy, safety boundaries, expected outputs, cleanup, and learning objectives. Leave PR comments or push a review branch.

4. Ask Codex:
Apply Claude's review comments and update the PR.

5. You review the PR.

6. You merge to main.

7. You run the lab locally.

8. You save outputs into the lab results folder.

9. Ask either agent:
Add these results to lab 002, update results.md, and open a PR.

PART 41 - Troubleshooting

Problem:
Codex does not see GitHub tools.

Fix:
- Confirm Docker is running.
- Confirm GITHUB_PAT is set.
- Confirm ~/.codex/config.toml exists.
- Confirm token has repo permissions.
- Restart Codex.

Problem:
Claude Code does not see GitHub MCP.

Fix:
- Run claude mcp list.
- Run /mcp inside Claude Code.
- Re-add the server with claude mcp add.
- Confirm GITHUB_PAT is set.
- Confirm your token has Contents, Issues, and Pull request permissions.

Problem:
Agent wants to change live machines.

Fix:
- Stop it.
- Update AGENTS.md and CLAUDE.md.
- Repeat: repo-only work unless explicitly authorized.

Problem:
Agents overwrite each other.

Fix:
- One issue per lab.
- One branch per agent.
- No direct commits to main.
- Use PR review flow.

Problem:
Secrets got committed.

Fix:
- Rotate the token immediately.
- Remove the secret from the repo.
- Add .gitignore rules if needed.
- Consider GitHub secret scanning.
- Do not reuse that token.
